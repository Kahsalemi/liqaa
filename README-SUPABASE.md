# 🤝 لقاء — دليل تفعيل Supabase (المصادقة + الحفظ السحابي + RLS)

التطبيق يعمل حالياً **بدون إنترنت كوضع ضيف** كما هو — وتفعيل السحابة اختياري ودقيقتان فقط.

---

## ١) أنشئ مشروع Supabase
1. اذهب إلى **supabase.com** وسجّل دخول
2. **New project** → اختر اسماً مثل `liqaa` وكلمة مرور لقاعدة البيانات
3. أقرب منطقة: **Frankfurt (eu-central-1)** ثم **Create**

## ٢) نفّذ مخطط قاعدة البيانات وسياسات RLS
1. من القائمة الجانبية: **SQL Editor → New query**
2. انسخ محتوى ملف **supabase-schema.sql** كاملاً والصقه ثم **Run**
3. سيتم إنشاء جدولين `meetings` و`agenda_items` مع سياسات
   **Row Level Security** التي تضمن أن كل مستخدم لا يرى إلا جلساته وحده

## ٣) انسخ مفاتيح الاتصال
1. **Settings → API**
2. انسخ **Project URL** → ضعه في `supabase-config.js` مكان `SUPABASE_URL`
3. انسخ **anon public** → ضعه مكان `SUPABASE_ANON_KEY`

## ٤) فعّل المصادقة بالبريد
- القائمة: **Authentication → Providers → Email** (مفعّل افتراضياً)
- للتجربة السريعة يمكنك تعطيل "Confirm email" من
  **Authentication → Sign In / Providers →Email**           (أو اتركه للإنتاج)

## ٥) جرّب
1. افتح الموقع → زر **🔑 دخول → حساب جديد**
2. أدخل بريدك وكلمة مرور (6+ أحرف)
3. تُستورد جلستك المحلية تلقائياً كبطاقة أولى في مكتبتك ☁️
4. كل تعديل يُرفع تلقائياً — استعرض/افتح/احذف من **🗂️ جلساتي**

---

## 🔒 كيف تعمل الحماية (RLS)؟
- كل صف في `meetings` يحمل `user_id` من جلسة الدخول تلقائياً
- السياسات: `select / insert / update / delete` كلها بشرط `user_id = auth.uid()`
- المحاور في `agenda_items` محمية أيضاً، ولا يمكن إدراج محور لجلسة ليس ملكك
- مفتاح `anon` العام آمن في المتصفح — فلا يمكن تجاوز السياسات حتى لو عدّل أحد الكود

## 🌐 النشر على GitHub Pages
ارفع مع `index.html` المحدّث الملفات: `supabase-config.js` و`supabase-app.js`
(ويمكن رفع `supabase-schema.sql` للتوثيق) — ثم أخبرني لتحديث النسخة المنشورة.
